GitHub release, host update, and encrypted backup automation (prepared locally)
- Added a push-to-`main` release workflow that builds Linux x86_64 and ARM64 binaries, packages them, publishes SHA-256 checksums, and creates a commit-specific private GitHub Release. The old x86_64 build workflow remains available manually to avoid duplicate automatic builds.
- `starter.js` can opt into private-release updates with `OMNICORE_AUTO_UPDATE=1` and a host-only read token. It selects the host architecture, verifies the downloaded binary against the release checksum, atomically replaces the local binary, and asks the supervisor to restart the bot. Auto-update polls every five minutes by default and is disabled unless configured.
- Added the binary's `--snapshot-database <destination>` mode using SQLite `VACUUM INTO` for a consistent online snapshot, including committed WAL data. The Node startup helper checks every 6 hours by default, hashes snapshots and skips unchanged databases, gzip-compresses and AES-256-GCM encrypts changed snapshots, uploads them as assets on a separate prerelease, and retains 14 days by default. If the local DB is missing, it restores the newest valid encrypted snapshot before bot startup; a failed restore leaves a persistent upload-block marker to protect remote data. Backups are disabled by default; plaintext database files are never uploaded. Added `restore-backup.js` for manual decryption/decompression to a new file.
- Manual owner/permissions-panel database downloads now produce JS-style ZIPs containing the SQLite file at Deflate level 9; their snapshot is generated with `VACUUM INTO` to include committed WAL data consistently.
- JS backup parity comparison: `backupService.js` uses WAL checkpoint + Deflate-9 ZIP for owner-triggered downloads; Rust now emits the same ZIP shape. `tools/github-backup.js` snapshots every 6 hours, skips unchanged DB hashes, restores when the local DB is missing, and blocks uploads after restore failure. Rust now matches those operational safeguards, while intentionally using a compressed AES-256-GCM encrypted asset on a `database-backups` prerelease in this same repo (JS stores unencrypted gzip in a separate private Contents-API repo). Rust also retains backup assets for 14 days by default.
- Host-side setup requires a private-repo read token for updater access, a repo-scoped Contents read/write token for backup release assets (can be the same token), a 32-byte `OMNICORE_BACKUP_KEY` stored only on the host and separately backed up, and `OMNICORE_AUTO_UPDATE=1` / `OMNICORE_BACKUP_ENABLED=1`.
